# ✨ MAGIC RISK ARTICULATION - USER GUIDE

## 🎯 **What is Magic Risk Articulation?**

Magic Risk Articulation is an AI-assisted feature that helps you create high-quality, structured risks by analyzing contextual information about your processes, systems, or operations.

Instead of manually filling out complex risk fields, you can:
- **Paste project descriptions, SOPs, or operational context**
- **Upload relevant documents (PDF, TXT, JSON)**
- **Click "✨ Articulate Risk" to auto-generate structured content**

## 🚀 **How to Use Magic Risk Articulation**

### **Step 1: Access the Feature**
1. Navigate to **Risk Register**
2. Click **"Add New Risk"**
3. Look for the **"AI-Assisted Risk Articulation"** section
4. Click **"Show Magic Tools"** to expand the section

### **Step 2: Provide Context**
Choose one or both methods:

#### **Method A: Paste Text Context**
```
Paste project description, SOP, policy excerpt, or operational context here...

Examples:
• "Our critical database server handles all customer transactions and must be available 24/7 with automatic failover"
• "The payment processing system handles vendor payments and must comply with SOX financial regulations"
• "Manufacturing process with quality control checkpoints and automated defect detection"
```

#### **Method B: Upload Document**
- Click **"Choose File"**
- Select PDF, TXT, or JSON file
- Supported formats: `.pdf`, `.txt`, `.json`

### **Step 3: Select Department**
**Important:** Select your department first, as it determines the analysis patterns:
- **IT**: Focuses on servers, networks, security, databases
- **Finance**: Focuses on payments, compliance, transactions
- **Operations**: Focuses on processes, equipment, safety

### **Step 4: Articulate the Risk**
1. Click **"✨ Articulate Risk"**
2. Watch as the system analyzes your context
3. Review the auto-filled fields
4. **Edit any content** as needed
5. Click **"Create Risk"** to save

## 🎨 **What Gets Auto-Filled**

### **Basic Information**
- **Risk Description**: Structured description based on context analysis
- **Process/Function**: Uses your input or generates from context

### **Risk Assessment (FMEA)**
- **Potential Failure Mode**: Specific failure scenarios identified
- **Potential Effects**: Business impact based on context
- **Potential Causes**: Root causes derived from analysis

### **Risk Ratings (1-10 Scale)**
- **Severity**: Impact assessment (6-9 based on context criticality)
- **Occurrence**: Likelihood based on operational context
- **Detection**: Current control assessment

### **Controls & Actions**
- **Preventive Controls**: Suggested measures from context analysis
- **Recommended Actions**: Specific mitigation steps

## 📊 **Department-Specific Intelligence**

### **IT Department Examples**
```
Context: "Critical database server with customer data"
→ Risk: "Server hardware failure or outage in Database Operations"
→ Effects: "Business operations disruption, data unavailability"
→ Actions: "Implement redundant servers, regular backups"
```

### **Operations Department Examples**

## 🔍 **Smart Analysis Features**

### **Keyword Recognition**
The system recognizes department-specific keywords:
- **IT**: server, network, database, security, software, hardware
- **Finance**: payment, transaction, accounting, audit, compliance
- **Operations**: process, equipment, maintenance, supply, production

### **Context Pattern Matching**
- **Critical/High-risk contexts** → Higher severity ratings
- **Compliance/Regulatory mentions** → Enhanced detection requirements
- **Automation/Digital systems** → Different failure modes than manual processes

### **Intelligent Suggestions**
- **Backup/Redundancy mentions** → Suggests monitoring actions
- **Training requirements** → Includes training in preventive actions
- **Audit/Review processes** → Suggests regular assessment actions

## 📋 **Best Practices**

### **Context Quality**
- **Be specific**: "Critical customer database server" vs "Database server"
- **Include constraints**: "Must be available 24/7", "SOX compliant"
- **Mention stakeholders**: "Affects customer experience", "Regulatory requirements"

### **File Upload Tips**
- **PDF documents**: Policy documents, SOPs, architecture diagrams
- **TXT files**: Process descriptions, requirements documents
- **JSON files**: Configuration files, system specifications

### **Review & Edit**
- **Always review** auto-generated content before saving
- **Adjust ratings** based on your specific risk tolerance
- **Add department-specific** details not captured by AI
- **Customize actions** for your organization's processes

## ⚠️ **Important Notes**

### **Data Privacy**
- Uploaded files are **processed temporarily** and **not stored**
- Context text is **used only for analysis** and **not persisted**
- All processing happens **client-side** for privacy

### **Editability**
- **All fields remain editable** after articulation
- **No forced acceptance** of generated content
- **Full control** over final risk content

### **Audit Trail**
- **Usage is logged** for compliance
- **Tracks articulation method** (text/file)
- **Maintains full auditability**

## 🎯 **Example Workflow**

```
1. User pastes: "Our critical payment system processes $10M daily and must comply with SOX regulations"

2. System analyzes:
   - "payment system" → Finance department patterns
   - "critical" → High severity rating
   - "SOX compliance" → Regulatory focus
   - "$10M daily" → High business impact

3. Auto-generates:
   - Description: "Risk of payment processing failure in critical SOX-compliant system"
   - Effects: "Financial losses up to $10M daily, regulatory penalties"
   - Severity: 9, Occurrence: 3, Detection: 5
   - Actions: "Dual authorization, automated controls, regular audits"

4. User reviews, adjusts, and saves the risk
```

## 📞 **Troubleshooting**

### **"No context provided"**
- **Solution**: Enter text in the context field or upload a file

### **"Irrelevant results"**
- **Solution**: Provide more specific context or select correct department

### **"File not supported"**
- **Solution**: Use PDF, TXT, or JSON files only

### **"Risk not saved"**
- **Solution**: Check for validation errors, ensure required fields are filled
